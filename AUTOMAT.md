# Instrukcja porannego automatu

Ten plik czyta codziennie o 6:52 zadanie w chmurze Claude „Mieszkania do 200 tys. Małopolska – aktualizacja danych (repo)”. Zadanie ma krótkie polecenie: przeczytać ten plik i wykonać go. Żeby zmienić działanie automatu, zmień ten plik, zrób commit i push na main – zmiana zadziała od następnego przebiegu.

Codzienna aktualizacja danych strony z mieszkaniami do 200 tys. zł w Małopolsce. Strona: https://gebrei.github.io/licytacje-malopolska/ (GitHub Pages z repozytorium GebreI/licytacje-malopolska, gałąź main). Repozytorium jest JEDYNYM źródłem kodu i danych. Zmieniasz WYŁĄCZNIE pliki w folderze data/ (licytacje.json, ceny_rynkowe.json, historia_cen.json, ogloszenia.json). Nie zmieniaj data/koszty_stawki.json ani plików strony (index.html, app.js, slownik.js, CLAUDE.md, README, AUTOMAT.md). Nie używaj dashboardu w aplikacji Claude (jest archiwum). Odpowiadaj po polsku.

KROK 0 – repo: repozytorium GebreI/licytacje-malopolska jest już sklonowane w katalogu roboczym (to źródło zadania). Przejdź na gałąź main i zrób git pull origin main. Przeczytaj obecne pliki z data/ – to jest stan wyjściowy (poprzednia lista ofert, ceny, historia, ogłoszenia).

KRYTERIA: tylko mieszkania (nie lokale użytkowe, nie domy), województwo małopolskie, cena do 200 000 zł, tylko aktywne (nie zakończone / nie archiwalne / termin nie minął). TYLKO CAŁE MIESZKANIA (100% własności): NIE pobieraj udziałów (np. „udział 1/2”, „1/8 części”, „udział we współwłasności”, mikrolokale sprzedawane jako udział). Gdy z karty nie wynika, czy to całość, otwórz ofertę i sprawdź; w razie wątpliwości pomiń. Rodzaje sprzedaży (pole rodzaj): "komornicza" (licytacje komornicze), "syndyk" (sprzedaż od syndyka/likwidatora), "przetarg" (gminy, miasta, spółdzielnie, spółki Skarbu Państwa, KOWR, inne instytucje), "bank" (banki, firmy windykacyjne), "ogłoszenie" (zwykłe ogłoszenia sprzedaży, rynek wtórny).

ŹRÓDŁA OFERT (oficjalny licytacje.komornik.pl i elicytacje.komornik.pl blokują automatyczny odczyt – NIE obchodź tego żadną inną drogą; tak samo nie obchodź blokad innych serwisów, np. otodom/olx/PKO – jeśli WebFetch zwraca błąd, pomiń). Użyj WebFetch:
1. https://listaprzetargow.pl/oferty/mieszkania/malopolskie/cena-do-200 – WSZYSTKIE oferty przed sekcją "Zakończone" (licytacje komornicze, przetargi, syndyk; jeśli aktywne ciągną się na ?page=2, pobierz też ją). Rodzaj z URL oferty: "licytacja-komornicza" → komornicza, "syndyk" → syndyk, "przetarg" → przetarg. Data na karcie listaprzetargow to termin wpłaty wadium/rękojmi → pole termin_wadium. Dla nowych ofert innych niż komornicze otwórz stronę oferty: sprawdź współrzędne mapy / gminę – listaprzetargow bywa źle przypisany do województwa (np. „Kotliska” to Dolny Śląsk – wyklucz oferty spoza Małopolski), oraz udział, piętro, wadium.
2. Adradar (oferty nie-ARCHIWALNE z ceną ≤ 200 000 zł; kolejne strony ?page=2… tylko dopóki zawierają nie-ARCHIWALNE): https://przetargi.adradar.pl/p/mieszkania/27529/ma%C5%82opolskie/licytacje_komornicze (rodzaj komornicza), …/zakup_od_syndyka (syndyk), …/miasto, …/spoldzielnia_mieszkaniowa, …/spolka_skarbu_panstwa (przetarg) – ten sam początek adresu https://przetargi.adradar.pl/p/mieszkania/27529/ma%C5%82opolskie/. "Termin" z adradar to data licytacji/przetargu → pole termin. Dla komorniczych z opisu: "pierwsza"/"druga" licytacja; "w trybie elektronicznym" → tryb "e-licytacja", inaczej "stacjonarna". Dla innych rodzajów licytacja = "" i tryb = "".
3. Zwykłe ogłoszenia i banki: https://www.domiporta.pl/mieszkanie/sprzedam/malopolskie?Price.To=200000 (wszystkie strony wyników). Otwórz każde NOWE ogłoszenie: ustal formę własności (odrębna własność / spółdzielcze / udział we współwłasności), rynek, czy sprzedaje syndyk/komornik/bank (wtedy rodzaj syndyk/komornicza/bank i połącz z ofertą z listaprzetargow jeśli to ta sama), termin składania ofert. Pomijaj: rynek pierwotny/deweloperski, lokale użytkowe (także gdy opis mówi „lokal użytkowy”), ogłoszenia bez ceny, sprzedaż od syndyka z terminem ofert, który minął. Mikrolokale sprzedawane jako „udział we współwłasności z prawem wyłącznego korzystania” to udziały – pomijaj. Banki: spróbuj też https://www.pekao.com.pl/nieruchomosci/lista-nieruchomosci/oferta.html (mieszkania w małopolskim ≤200 tys.); jeśli nic – trudno.
Połącz duplikaty (ta sama miejscowość + cena ±1 zł + podobny metraż) w jeden wiersz z url (listaprzetargow, a gdy brak – pierwsze źródło) i url2 (drugie źródło). Dla komorniczych tylko z listaprzetargow, jeśli to możliwe, otwórz stronę oferty, żeby ustalić, która to licytacja (pierwsza/druga) – strona liczy z tego sumę oszacowania i rękojmię.

KROK B – data/licytacje.json: nowa lista ofert w tym samym schemacie (tablica obiektów): id ("lp-<numer oferty listaprzetargow>", "ad-<numer adradar>" gdy tylko z adradar, "do-<numer domiporta>" gdy tylko z domiporta; zachowaj dotychczasowe id dla znanych ofert), rodzaj ("komornicza"/"syndyk"/"przetarg"/"bank"/"ogłoszenie"), miejscowosc (dokładnie taka nazwa jak w ceny_rynkowe, jeśli miejscowość już tam jest; dla wsi nazwa wsi), lokalizacja (ulica/osiedle/gmina lub ""), cena (liczba), m2 (liczba, bez piwnicy), cena_m2 (liczba, zaokrąglona), pokoje (liczba lub null), typ (zawsze "Całe mieszkanie" – udziałów nie zapisujemy), udzial (zawsze null), licytacja ("pierwsza"/"druga"/""), tryb ("e-licytacja"/"stacjonarna"/""), termin ("RRRR-MM-DD" lub null – data licytacji / przetargu / otwarcia ofert), termin_wadium ("RRRR-MM-DD" lub null – rękojmia/wadium lub termin składania ofert), rabat_pct (liczba ujemna jeśli pokazana, inaczej null), uwagi (krótko, własnymi słowami; WAŻNE – strona rozpoznaje ryzyka po słowach w uwagach, więc gdy dotyczy, użyj dokładnie: "służebność" dla służebności/dożywocia, "brak prawnie zabezpieczonego dojazdu" przy problemie z dostępem do drogi, "piec węglowy do wymiany" lub "do wymiany" przy instalacjach do wymiany; dla syndyka/przetargu dopisz kwotę wadium i czy cena jest netto), dodano (data pierwszego zauważenia – stara dla znanych, dzisiejsza dla nowych), sprawdzono (DZISIEJSZA data dla każdej oferty, którą widzisz dziś w źródłach), url, url2 ("" gdy brak). Usuń wszystkie udziały (typ "Udział" lub niepuste udzial), także te z poprzedniej listy. Usuń też oferty, których termin (licytacji/przetargu) lub – gdy brak terminu – termin_wadium minął, lub które źródła oznaczają jako zakończone/archiwalne, lub ogłoszenia, których już nie ma w domiporta. Jeśli tylko część źródeł nie działa, zachowaj oferty z niedziałających źródeł (bez zmiany pola sprawdzono) i wspomnij o tym w podsumowaniu. Jeśli ŻADNE źródło ofert nie dało się odczytać – nie zmieniaj żadnych plików, nie rób commita (strona sama pokaże, że dane są nieaktualne).

KROK C – data/ceny_rynkowe.json. Dla KAŻDEJ miejscowości z nowej listy ofert, której brak w ceny_rynkowe, dodaj wiersz w schemacie: miejscowosc, gmina, powiat (bez słowa "powiat", małymi literami, z polskimi znakami, np. KROK D – zapis i publikacja:
1. Zapisz zmienione pliki do data/ w repozytorium (JSON, UTF-8, ensure_ascii=False, tablica obiektów). Sprawdź, że każdy plik w data/ się parsuje i jest tablicą.
2. Jeśli git status jest pusty – nic nie rób dalej.
3. git add data/; commit z autorem "Claude <noreply@anthropic.com>" i wiadomością "Aktualizacja danych RRRR-MM-DD". Przed push: git fetch origin main i git rebase origin/main (ktoś mógł w tym czasie wypchnąć zmiany kodu z Claude Code; konflikt może dotyczyć tylko data/ – wtedy weź swoje, dzisiejsze dane). git push origin HEAD:main. Jeśli push zostanie odrzucony (brak uprawnień), nie ponawiaj w pętli – zapisz to w podsumowaniu.
